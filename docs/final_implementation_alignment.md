## Final System Claim

Uritect performs fully offline, markerless, ten-analyte semiquantitative urine
dipstick classification on Android. The app does not use a Python server, HTTP
endpoint, cloud storage, Firebase, remote APIs, binary screening, Bayesian
posterior scoring, unsupported likelihood-ratio weights, priors, or posterior
thresholds.

## Objective 4 Replacement

Evaluate the Uritect mobile application as an offline clinical decision-support

with separate rule-based clinical outputs for localized UTI-related findings,
systemic warning symptoms, renal-related follow-up, and metabolic follow-up.

## Chapter 3 Methodology Replacement

The final image-processing workflow is markerless. Each captured image is
decoded on device, orientation variants are evaluated, and the strip is
localized using strip geometry and color/chroma activity rather than a
black/white macromarker. The app applies gray-world illumination normalization
using low-saturation neutral strip/plastic pixels near the detected strip.
Reagent-pad row centers are detected from saturation/chroma activity. A scan is
accepted only when one plausible strip and ten reliable pad regions are found.
Blank, blurred, partial, wrong-object, multiple-strip, very dark, overexposed,
or otherwise invalid images are rejected with a retake message rather than
fabricated analyte results.

The model workflow is semiquantitative only. The frozen production model is
`production_semiquant_knn_markerless_roi_topfix_v3_20260908`. The app packages the
same model as `assets/production_semiquant_model.json`, and the Python testing
path uses the corresponding frozen model directory in
`pipeline/output/semiquant_models`.

Final evaluation removes exact duplicate feature rows, groups related images by
specimen identity before splitting, and keeps Cool, Warm, and Daylight variants
from the same specimen on the same side of the split. Metrics are reported
separately as individual-analyte accuracy, exact whole-scan all-ten-correct
accuracy, per-analyte accuracy, and end-to-end scan outcomes.

## Chapter 4 Implementation Replacement

The Android production scan path is implemented in
`uritect_app/lib/services/local_scan_analysis_service.dart`. The public app
service in `uritect_app/lib/services/scan_analysis_service.dart` delegates
directly to this local analyzer. The Android manifest removes internet and
network-state permissions from the main production manifest.

The production model is generated by:

```text
python pipeline/freeze_production_semiquant.py
python pipeline/export_production_model_json.py
python pipeline/validate_production_json_model.py
```

`validate_production_json_model.py` verifies prediction parity between the
frozen Python model and the Android JSON model. The current parity check
validated 2,000 feature-row predictions with zero mismatches.

```text

```

## Clinical Interpretation Replacement

Clinical interpretation is rule-based and separated into four outputs:

- Localized UTI-related findings: leukocyte esterase, nitrite, dysuria,
  frequency/urgency, visible hematuria, and suprapubic pain.
- Systemic warning symptoms: fever/chills, flank/back pain, and
  nausea/vomiting.
- Renal-related follow-up: protein abnormality, blood-related findings when
  incorporated into the approved rule set, edema, and other approved evidence.
- Metabolic follow-up: glucose and ketone abnormalities.

These outputs are not merged into a single artificial disease probability.
